# How the core works

`cmd/netrix` reads one bounded YAML/JSON configuration, validates it, installs signal handling and starts the selected Linux transport. Routine status logs omit configured paths and peer addresses. Local startup errors from a configured TCP listener or dialer can include its endpoint; these errors are not sent to a vendor or analytics service.

For normal reverse tunnels, the server accepts peer connections and owns forwarding listeners. The client dials it and accepts stream requests to local backends. Direct mode reverses connection initiation: the server dials the client. The public server still owns forwarding listeners, and their backends remain on the public client. Pools retry disconnected connections; session selection favors an available SMUX session with fewer open streams.

Each ordinary path creates its configured number of `PORTS` connections. Enabling TUN adds a separate pool of `TUN` connections of the same size, preserving reference role isolation. Port forwarding and TUN packets can therefore operate together without sharing or starving the wrong role pool.

The connection stack is: configured TCP/TLS/WebSocket/KCP/raw carrier → optional encrypted or padded records → peer role/authentication line → optional compression → SMUX. A multiplex count above one adds outer SMUX streams containing independent inner SMUX sessions. Stream control lines select `CONNECT`, `UDP` or `TUN`.

The `internal/wire` package preserves control-line read-ahead and implements UDP records (`BE16 address length`, `BE16 payload length`, address, payload) and TUN packets (`BE32 length`, packet). UDP flow identifiers are returned through the same local socket. Payload, address and flow-state limits bound memory use.

Accepted `CTRL` streams answer the reference's `PING <timestamp>` messages with `PONG <timestamp>`, preserving the trimmed timestamp text. Control lines are bounded and idle streams expire after ten minutes. The rewrite uses SMUX keepalive for its own sessions; it does not recreate a separate client control heartbeat schedule.

`internal/record` implements recovered record formats with full writes, truncation checks and authenticated ciphertext. Ordinary encrypted records have a two-byte length, a 12-byte directional nonce and AEAD ciphertext. The length is authenticated; plaintext begins with a one-byte padding count. The independent default derives a fresh session key from a local secret plus random contributions from both peers; this `NRX4` exchange deliberately differs from the reference. Explicit v3 compatibility retains the reference static key and counter behavior.

Compression uses Zstd blocks, LZ4 frames or Klauspost S2 blocks. The reference labels S2 as “Snappy”; ordinary `golang/snappy` is not a substitute. Each compression record contains a four-byte length, a one-byte flag and encoded or plain bytes. Outer and inner streams use the same configured codec when active.

`internal/tun` creates owned, nonpersistent Linux TUN queues with `IFF_NO_PI`, configures explicit addresses/routes through structured `ip` arguments and closes the device on shutdown. It refuses to take over an existing interface. Route additions never replace unrelated routes. Each queue carries complete IP packets over bidirectional streams. Server mode opens those streams in both normal and direct configurations; clients use the accepted streams for replies. A long-lived reader per device queue continues across stream replacement. Stream slots are bounded and queue selection remains a local scheduling choice, not a wire field.

`internal/packet` handles bounded IPv4 headers, checksums, peer admission and owned socket filters. The recovered rawsocket mode is Ethernet/IPv4/TCP-shaped KCP traffic with an eight-byte inner envelope; it is separate from ordinary TCP and L3's real TCP carrier. Generic datagram wrappers alone do not establish rawsocket compatibility.

L3 ICMP derives its outer echo identifier from the session ID: the low 16 bits of `sid XOR (sid >> 16)`, with `0x4e45` replacing zero. The same value is required by receive admission and the owned socket filter. L3 `spoof_src_ip` replaces only the transmitted source; packets still go to the real configured peer. `spoof_dst_ip` describes that peer's expected spoofed source for receiving. The local receive destination remains the real local address. These carrier fields do not change the session-ID or key derivation rules.

`internal/l3` contains the recovered `NL3X` framing and key derivation. Its logical fixed header is 16 bytes followed by an eight-byte sequence: total frame length is `16 + body_length`. Session IDs derive from canonical endpoints, carrier settings, parsed TUN IP addresses without prefix lengths, and local encryption settings. Encryption uses PBKDF2-HMAC-SHA256 and an explicit 12-byte nonce. This implementation fills all 96 nonce bits from cryptographic randomness for every encrypted packet, replacing the reference's short random prefix plus counter. The explicit nonce field and authenticated framing remain compatible. Each sending instance is bounded to at most 2^32 encrypted packets and stops on entropy failure. Flags select encrypted data, heartbeat or inner fragmentation. AEAD authenticates data and heartbeat records when encryption is enabled; plaintext L3 has no MAC or authentication handshake. Its session ID is not a substitute for authentication; a PSK is not used in the plaintext L3 scope. Exact runtime status belongs in the compatibility report.

`internal/firewall` provides optional L2TP/IPsec UDP port forwarding using uniquely owned NAT chains. Its default DNAT destination is the local TUN address; an explicit destination can route through the tunnel. Cleanup removes only this instance's rules. The operator configures global forwarding and firewall policy; the core does not flush rules or silently alter host-wide sysctls.

There is no registration or commercial IP verification step in this architecture. The core's usable destinations and routes come from operator configuration.

The vendored SMUX implementation includes a local repair that retains unread response buffers after both sides send FIN. Its optimized copy path treats a fully drained EOF as successful completion. This preserves replies to a request that closes its write side before reading the answer; the stream frame format is unchanged. The upstream license and authors remain credited, and the patch is described in `vendor/github.com/xtaci/smux/IR_SPOOF_PATCH.md`.
