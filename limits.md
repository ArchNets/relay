# Limits and intentional differences

This is independently written Go source reconstructed from runtime metadata, machine code and measured packet behavior. It is not the original source and cannot produce a byte-identical executable. The original obfuscated compiler/module versions are unavailable; privacy removal and security improvements deliberately change behavior and bytes.

There is no vendor IP license check, public-IP query, embedded vendor cache, analytics, ACME service or automatic updater. Explicitly configured hostnames still use ordinary DNS. Explicit PROXY protocol forwards source metadata only to the configured backend. A local PSK is not vendor registration. Ordinary token authentication needs encryption or TLS to hide the token. Encrypted L3 uses AEAD authentication; plaintext L3 has no cryptographic authentication and does not use a PSK in its session ID.

Ordinary encrypted peers use a new random session-key exchange by default. The explicit `-compat-v3` option selects recovered legacy encrypted records for interoperability, including the reference's repeated key/counter design and conditional compression behavior. This option does not bring back vendor licensing. L3 retains its explicit nonce field but uses full 96-bit random nonces rather than a short random prefix.

The reference's `realitymux` is observed browser-shaped TLS. Xray REALITY authentication was not established by the evidence. Nonempty `public_key` or `short_id` is therefore rejected; it must not appear to authenticate a peer. TLS certificate verification is enabled by default. Supply local certificates/trust roots; disabling verification is an explicit operator choice.

The following recovered configuration names do **not** recreate the reference's scheduling/allocator policy: advanced `cleanup_interval`, `session_timeout`, `connection_timeout`, `stream_timeout`, `stream_idle_timeout`, `anti_dpi_delay_ms`, `stream_queue_size`, `buffer_pool_size`, `large_buffer_pool_size`, `udp_frame_pool_size`, `udp_data_slice_size`, `aggressive_pool`, and the ordinary top-level `heartbeat`. Nondefault values are rejected rather than silently ignored. SMUX keepalive, TCP keepalive, retry/dial deadlines, socket buffer sizes, UDP flow limits/timeouts and L3 heartbeat settings are implemented separately. Profile names select reconstructed SMUX defaults; complete original performance tuning is not established. Routine logging stays minimal regardless of `verbose`.

Use `netrix -config FILE`, `-check`, `-version` and optional `-compat-v3`. A leading `server` or `client` verifies the configuration role. The original flag-only core interface and undocumented `debug-streams`/`reset-streams` diagnostic commands are not recreated. The included manager supplies the documented create/install/start/stop/status/update/rollback/remove workflow through local configuration files.

Packet and spoofing modes require suitable Linux privileges and network topology. Spoofed packets are constrained to the configured peer and owned capture sockets. Internet routing of spoofed source addresses is not implied by a local lab pass. TUN creation refuses existing interfaces and owns only its added routes. Automatic firewall/global route takeover is not provided.

Original observations, private reference-derivative comparisons and replacement-to-replacement tests are separate evidence categories in the compatibility report. No modified commercial binary or private lab key is shipped. Dependency licenses remain intact.

L3 datagram send/receive buffer requests currently use the larger configured value for both directions; real TCP uses the individual values. Before the first accepted sequenced peer record (AEAD authenticated in encrypted mode), L3 waits for the peer rather than applying its established-peer heartbeat timeout. These are runtime differences, not recovered packet-format changes.

For ordinary TUN interoperability with reference peers, use `tun.streams: 1`: the measured comparisons passed in both roles and reverse/direct modes, including simultaneous port forwarding. Independent peers passed the same coexistence workflow with two queues. A separate reference-only two-queue observation admitted interface addresses, peer routes and an initial ping, then failed a later normal ping; the one-queue observation passed. This does not by itself prove an upstream defect or establish all multiqueue combinations. See the [test report](test-report.md) for the exact measured scope.
