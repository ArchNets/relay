ساخت و نصب Netrix از سورس با Go و ir_spoof

ir_spoof

می‌خوای به‌جای فایل آماده، خودت هسته رو از سورس بسازی؟ این راهنما از باز کردن ZIP شروع می‌شه و تا نصب همون خروجی روی سرور می‌ره. پروژه Netrix · ir_spoof نسخه 0.1.0 با Go نوشته شده؛ مدیر سرویس‌ها هم Pythonه. این بازسازی مستقلِ عملکرد برنامه‌ست، نه سورس اصلی و نه فایل اجرایی بایت‌به‌بایت یکسان.

چی لازم داری

  • یک لینوکس amd64 با glibc؛ مثل Ubuntu یا Debian. فایل آماده این بسته مخصوص amd64ه و روی Alpine/musl به‌تنهایی اجرا نمی‌شه.
  • Go نسخه 1.26 یا جدیدتر، از قبل نصب‌شده. تست ساخت آفلاین این انتشار با Go 1.27.2 انجام شده.
  • Python 3.10 یا جدیدتر و systemd برای نصب و مدیریت سرویس‌ها.
  • ابزارهای unzip، tar و sha256sum برای باز کردن بسته و بررسی فایل‌ها. برای TUN هم iproute2 لازمه.
  • ساخت و تست معمولی با کاربر عادی انجام می‌شه؛ فقط مرحله نصب و مدیریت سرویس‌ها sudo می‌خواد.
uname -m
go version
python3 --version
command -v unzip tar sha256sum ip
systemctl --version

روی amd64، خروجی uname -m باید x86_64 باشه. اگر Go یا ابزارهای سیستم نصب نیست، اول با روش رسمی یا مدیر بسته لینوکست نصبشون کن. آفلاین بودن ساخت یعنی بعد از آماده بودن این ابزارها، وابستگی‌های Go از پوشه vendor همین سورس خونده می‌شن؛ نصب اولیه ابزارها ممکنه اینترنت بخواد.

ZIP کامل و بعد سورس رو باز کن

فایل netrix-ir_spoof-complete-linux-amd64-0.1.0.zip رو روی لینوکس بذار و از همون پوشه این دستورها رو بزن. اسم فایل‌ها رو تغییر نده تا مسیرهای این راهنما دقیقاً جور دربیان.

unzip netrix-ir_spoof-complete-linux-amd64-0.1.0.zip
cd netrix-ir_spoof-0.1.0
sha256sum -c SHA256SUMS
unzip netrix-ir_spoof-source-0.1.0.zip
cd netrix-ir_spoof-source-0.1.0

برای همه فایل‌های فهرست‌شده باید OK ببینی. اگر FAILED دیدی، همون‌جا متوقف شو و فایل سالم رو دوباره بگیر. checksum جلوی خرابی یا تغییر فایل نسبت به فهرست رو می‌گیره؛ اعتماد به اصالت بسته هنوز به این بستگی داره که خود بسته و فهرست رو از جای مورد اعتماد گرفته باشی. اگر فقط ZIP سورس رو داری، همون رو باز کن و مستقیم وارد پوشه netrix-ir_spoof-source-0.1.0 شو. نسخه tar.gz سورس هم داخل بسته هست و می‌تونی به‌جای ZIP از اون استفاده کنی.

هسته رو بساز؛ بدون دانلود وابستگی

از ریشه سورس اجرا کن. این تنظیمات دانلود ماژول و دانلود خودکار toolchain رو خاموش می‌کنن. trimpath مسیرهای محلی ساخت رو از خروجی حذف می‌کنه و buildvcs=false مانع ثبت اطلاعات کنترل نسخه در فایل اجرایی می‌شه. خروجی قابل انتشار با نام build/netrix ساخته می‌شه.

export GOTELEMETRY=off GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off CGO_ENABLED=0
mkdir -p build
go build -mod=vendor -trimpath -buildvcs=false -ldflags='-s -w' -o build/netrix ./cmd/netrix
./build/netrix -version
sha256sum build/netrix

نسخه خروجی باید نام ir_spoof رو داشته باشه. اگر دوست داری همین کار کوتاه‌تر انجام بشه، به‌جای دستورهای ساخت بالا، از ریشه سورس sh scripts/build.sh رو اجرا کن؛ همون تنظیمات ساخت رو اعمال می‌کنه، نسخه رو چاپ می‌کنه و checksum می‌ده. هیچ‌کدوم رو با sudo اجرا نکن.

sh scripts/build.sh

نکته فنی کوتاه: CGO_ENABLED=0 این برنامه رو کاملاً استاتیک نمی‌کنه. بخش purego از loader سیستم استفاده می‌کنه؛ خروجی هنوز به loader استاندارد ELF و کتابخانه‌های glibc مثل libc، libpthread و libdl نیاز داره. نبودن gcc برای این دستور ساخت مشکلی نیست، ولی لینوکس مناسب برای اجرا لازمه.

قبل از نصب، تست‌ها رو اجرا کن

go test -mod=vendor ./...
PYTHONDONTWRITEBYTECODE=1 python3 -B scripts/test-manager.py

تست‌های Go و مدیر سرویس باید موفق باشن. بعضی تست‌های TUN به دسترسی‌های ویژه لینوکس نیاز دارن و با کاربر عادی ممکنه SKIP بشن؛ SKIP یعنی اون بخش این بار اجرا نشده. برای رد کردن این مرحله کل ساخت یا همه تست‌ها رو sudo نکن. تست واقعی ارتباط بین دو سرور، جای خودش رو داره و در راهنمای تونل انجامش می‌دیم.

همین خروجی رو نصب کن

حالا installer محلی رو با فایل ساخته‌شده و SHA-256 خودش اجرا کن. این هش، همون خروجی‌ای رو که ساختی برای نصب مشخص می‌کنه؛ لازم نیست با هش باینری آماده یکی باشه، چون نسخه Go و محیط ساخت می‌تونن فرق کنن. این نصب هیچ هسته‌ای رو از سایت سازنده دانلود نمی‌کنه.

sudo sh scripts/install.sh --binary build/netrix --sha256 "$(sha256sum build/netrix | cut -d' ' -f1)"
netrix -version
sudo netrix-manager

هسته در /usr/local/bin/netrix نصب می‌شه و netrix-manager منوی ساخت و مدیریت تونل رو باز می‌کنه. اگر فایل ناشناسِ قدیمی با همین اسم روی سرور باشه، installer خودکار جاش رو نمی‌گیره. جایگزینی نصب قدیمی فقط با گزینه‌های مهاجرت و هش دقیق فایل قبلی انجام می‌شه؛ توضیحش در docs/manager.md هست. برای یک شروع تمیز، از VM یا سرور آزمایشی جدا استفاده کن.

از ساخت هسته تا تونل واقعی

نصب به‌تنهایی تونل نمی‌سازه. همین نسخه رو روی سرور دوم هم نصب کن، بعد نقش server و client، آدرس همتا، پورت و نگاشت سرویس رو با راهنمای زیر تنظیم کن. منوی مدیر سرویس می‌تونه فایل تنظیمات و سرویس systemd رو بسازه و روشن کنه.

راهنمای راه‌اندازی تونل بین دو سرور: https://telegra.ph/نصب-Netrix-و-ساخت-تونل-بین-دو-سرور-با-ir-spoof-10-09

sudo netrix-manager status
sudo netrix-manager restart demo
sudo netrix-manager stop demo
sudo netrix-manager start demo

demo رو با اسم تونلی که خودت ساختی عوض کن. برای دستورهای بیشتر docs/manager.md رو بخون؛ README.md هم ساخت و نصب رو توضیح می‌ده. جزئیات هسته در docs/core.md و docs/wire-format.md هست. docs/test-report.md گزارش تست این نسخه و docs/limits.md تفاوت‌ها و محدودیت‌های ثبت‌شده رو داره.

حریم خصوصی و اعتبار پروژه

هسته و مدیر این نسخه، کلاینت لایسنس، جست‌وجوی IP عمومی، telemetry، analytics یا آپدیت خودکار ندارن. اتصال عادی فقط به همتا و مقصدهایی انجام می‌شه که خودت تنظیم می‌کنی؛ hostname هم طبیعتاً DNS می‌خواد. اگر PSK محلی بذاری، فقط برای احراز هویت بین سرورهای خودته و شناسه ثبت‌نام یا ابزار ردیابی نیست؛ برای مخفی موندن اون روی شبکه، رمزنگاری یا TLS رو روشن نگه دار.

انتشار مستقل و بازسازی: ir_spoof — https://t.me/ir_spoof. اعتبار و لایسنس وابستگی‌ها داخل سورس و بسته حفظ شده. این نسخه شامل باینری اصلی تجاری یا سورس اختصاصی اون نیست؛ ادعای یکسان بودن کامل رفتار و بایت‌ها هم نداره.
